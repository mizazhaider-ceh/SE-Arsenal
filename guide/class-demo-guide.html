🧭 The attack chain

Every real TikTok and Instagram account takeover you have ever seen follows the same five beats. Each tool in this lab owns one beat.

🔍 Sherlock RECON

Username search · 400+ sites · v0.16.2 · verified live in this lab

How hackers use it: a victim uses the same handle everywhere. One Instagram username becomes their TikTok, their GitHub, their dating profile, their gaming accounts. Sherlock finds them all in under a minute, and the attacker now knows where else to attack and what the victim cares about.
How it works: Sherlock carries a database of per-site detection rules. For each site it requests the profile URL and checks the response: an HTTP status code, a redirect, or a unique "user not found" string in the page body. Match means the account exists. No login, no API key, just public web requests, fired in parallel.

▶ Demo commands

# full sweep on a demo handle bin/sherlock demo_handle # focused: only the platforms the class cares about bin/sherlock --site Instagram --site TikTok demo_handle

What the class should notice: the result list is a map of a person's life, built from one word. Different passwords per site mean nothing if the profile itself tells the attacker the answers to the security questions.

🛡️ Prevention: vary usernames across important and casual accounts, keep personal accounts private, and remove bio links that chain your identities together.

🕵️ Maigret RECON

Username search · 3000+ sites · v0.6.6 · verified live in this lab

How hackers use it: Sherlock's bigger brother. Attackers run Maigret when they want the deep file: it does not just say an account exists, it reads the public profile and extracts extra identifiers, interests and tags, then follows newly found IDs recursively. One handle becomes a dossier.
How it works: same detection-rule engine as Sherlock, with a database of roughly 3000 sites, plus a parser layer (socid-extractor) that pulls structured data out of profile pages: display names, avatars, linked accounts, interest tags. It writes a tidy report you can open in the browser, perfect for showing a class what "public information" really adds up to.

▶ Demo commands

# deep sweep with a visual report bin/maigret demo_handle # one platform only, faster for live demos bin/maigret --site Instagram demo_handle

What the class should notice: the extracted interests. "Football, gaming, K-pop" is not trivia, it is the raw material for a bait message the victim will actually click.

🛡️ Prevention: audit yourself once a semester. Run your own handle through Maigret, see what a stranger sees, and lock down what you did not mean to publish.

🌾 theHarvester RECON

Email and subdomain harvesting · v4.11.1 · verified in this lab

How hackers use it: before attacking a company or a school, attackers collect its email addresses and subdomains from public sources. Every address found is a future phishing target, and the naming pattern (firstname.lastname@) tells them how to guess the rest.
How it works: theHarvester queries search engines and public APIs with crafted searches, then parses the results for email patterns and hostnames, and resolves subdomains through DNS. It never touches the target's servers directly in the basic mode, which is why it is so hard to detect.

▶ Demo commands

# harvest a demo domain (use example.com in class) bin/theharvester -d example.com -b duckduckgo,bing

What the class should notice: this is all legal, public data. The attack has not even started and the target list is already written.

🛡️ Prevention: organisations should publish fewer direct addresses (use contact forms and role aliases), and everyone should assume their email address is public knowledge. The secret must be the password and the second factor, never the address.

📧 Holehe RECON

Email account checker · 120+ sites · verified in this lab

How hackers use it: give Holehe one email address and it tells you where that person has accounts: Instagram, TikTok, Twitter, Spotify and more. That list is where password-reset abuse and credential stuffing will be aimed, because people reuse passwords.
How it works: Holehe abuses the "forgot password" flow. Sites answer differently for a registered email than for an unknown one (a different message, status or response body). Holehe sends the reset request, reads which answer came back, and marks the account as existing. The site leaks account existence by design, one reset form at a time.

▶ Demo commands

# check a demo mailbox you own bin/holehe demo@example.com # only show confirmed accounts bin/holehe --only-used demo@example.com

What the class should notice: no password was guessed and nothing was "hacked". A helpful user-experience feature quietly answers an attacker's question.

🛡️ Prevention: unique password per site (a password manager makes this painless), so one leaked list cannot unlock the rest. Sites should answer reset requests with one identical message either way.

🎣 Gophish BAIT + CAPTURE

Phishing simulation platform · v0.12.1 · verified in this lab

How the pros use it: this is the platform companies themselves run, legally, to train staff. It sends the campaign, hosts the landing page, and measures exactly who clicked, who typed credentials, and who reported it. Criminal crews use lookalike platforms for the same reason: phishing is a numbers game and dashboards win it.
How it works: a single Go binary with a built-in web server and database. You define a sending profile (SMTP), an email template, a landing page (which can clone a real page and capture the form), and a target group. Every link carries a unique tracking ID, so each click and submission is tied to a person. The admin panel lives on port 3333 and the first launch prints the admin password in the terminal.

▶ Demo commands

# start the platform, watch the terminal for the admin password bin/gophish # then open https://localhost:3333 and log in as admin

What the class should notice: the results page. One convincing email to 100 people, and the dashboard shows a click rate any marketer would envy. That is why this crime scales.

🛡️ Prevention: this is also the cure. Teams that run regular simulations and reward reporting (not punishment) cut their click rates dramatically. As a user: hover or long-press every link, and report suspicious mail instead of just deleting it.

🧰 SET · Social-Engineer Toolkit BAIT + CAPTURE

The classic attack framework · TrustedSec · menu verified in this lab

How hackers use it: SET is the grandparent of phishing frameworks, shipped with Kali for a decade. Its most famous trick is the Credential Harvester: it clones a real login page in seconds and logs everything typed into it. It also builds malicious files, QR codes and mass-mail campaigns from one menu.
How it works: the Site Cloner downloads the target page (HTML, images, styles), rewrites the login form so it POSTs to the attacker's machine instead of the real server, then serves the copy locally. The victim sees a pixel-perfect page. When they submit, SET records every form field to a report and, in the classic flow, redirects them to the real site so nothing feels wrong.

▶ Demo path

bin/setoolkit # 1) Social-Engineering Attacks # 2) Website Attack Vectors # 3) Credential Harvester Attack Method # 2) Site Cloner, then give it your lab IP and the page to clone

What the class should notice: the clone takes under a minute and needs zero skill. The barrier to this crime is not talent, it is distribution: getting the link in front of the victim.

🛡️ Prevention: the page is perfect, but the address is not. Train the reflex: never log in from a link. Close the message, open the official app, and log in there.

📱 Zphisher THE REAL-WORLD KIT

Prebuilt clone-page kit · Instagram and TikTok templates · verified in this lab

How hackers use it: this is the kit behind the scams your classmates actually receive: "get 10k free followers", "your account will be deleted, verify now", "blue tick verification". No skill needed: pick Instagram or TikTok from the menu, pick a tunnel, send the link. The kit does the rest, including logging the victim's IP address, browser and typed password.
How it works: three simple parts. (1) A folder of static template pages that copy the real login screens, plus bait variants like follower-boost pages. (2) A tiny PHP server that serves the template and writes submitted credentials and the visitor's IP to a file. (3) A tunnel (Cloudflare, ngrok or similar) that gives the attacker's home machine a public link with a trustworthy-looking HTTPS padlock. The padlock only proves the tunnel is encrypted, not that the site is honest.

▶ Demo commands

bin/zphisher # pick 02 Instagram or 10 TikTok, then 01 localhost for the classroom demo # log in on the fake page with the DEMO account, then read the captured file

What the class should notice: two tells survive every kit. The address is never the real domain (it is a tunnel address or a lookalike), and the bait always rushes you: free, urgent, or threatening. Real platforms never DM you a login link.

🛡️ Prevention: turn on two-step verification in the official app, use a password manager (it will refuse to fill your Instagram password on a fake domain, because the domain does not match), and treat every "free followers" offer as a confession that it is a scam.

👑 Evilginx BYPASS · BOSS LEVEL

Adversary-in-the-middle framework · v3.3.0 · verified in this lab

How hackers use it: "But I have two-factor authentication." Evilginx is the answer criminals found. The victim does everything right: real page, real password, real 2FA code. It does not matter, because they did it all through the attacker's proxy, and the attacker keeps the one thing that proves the login happened: the session cookie.
How it works: Evilginx is a reverse proxy. The victim connects to the attacker's server, which fetches the genuine site in real time, rewrites the domain names in the pages as they pass through, and relays everything both ways. The real site happily completes the password and 2FA checks, then issues session cookies, which the proxy copies as they flow past. The attacker imports those cookies into their own browser and is simply logged in, no password or code needed. A config file called a phishlet defines, per site, which domains to proxy and which cookies to steal.

▶ Demo commands

bin/evilginx # inside the console: # config → see and set the lab domain # phishlets → list the targets it can proxy # lures → create and inspect the bait links

What the class should notice: the page is not a copy this time, it is the real site, live. Every visual check passes. The only wrong thing is the domain in the address bar, one detail carrying the whole defence.

🛡️ Prevention: one defence truly beats this: passkeys and FIDO2 security keys. They cryptographically bind your login to the real domain, so on a proxy domain the login simply cannot be completed. App codes and SMS codes cannot do this. Turn on passkeys wherever they are offered.

🔬 Reading a link like a detective

The real domain is the part directly before the first single slash after https://. Everything before it is decoration the attacker controls.

LinkReal domainVerdict
https://www.instagram.com/logininstagram.com✅ Real
https://instagram.com.login-verify.xyzlogin-verify.xyz🚫 Fake, subdomain trick
https://login.instagram.com@evil-site.netevil-site.net🚫 Fake, the @ hides the true host
https://something.trycloudflare.comtrycloudflare.com🚫 Tunnel, no real brand logs you in here
https://instagrarn.com (with an "r n")instagrarn.com🚫 Lookalike spelling

Three more tells: the message rushes you (ban, prize, deadline), it arrived where the platform never contacts you (DMs, comments, WhatsApp), and your password manager suddenly refuses to fill the password. That refusal is a fire alarm, not a bug.

🛡️ The master prevention checklist

  • Passkeys first. Turn them on for Instagram, TikTok, Google, everywhere offered. They are the only common defence that defeats proxy phishing.
  • Two-step verification on, app-based where possible. It still stops the cheap kits and stolen password lists.
  • Unique password per account, stored in a password manager. The manager doubles as a fake-site detector: no autofill, no trust.
  • Never log in from a link in a message. Open the official app yourself. Every time, no exceptions for "urgent" ones, urgency is the tell.
  • Read the domain, not the page. Pages can be copied perfectly in a minute. Domains cannot be borrowed.
  • Shrink your public footprint. Private personal accounts, different handles for important accounts, and run Sherlock on yourself once a semester.
  • Check active sessions in the app settings after any scare, and log out everything you do not recognise.
  • Report, do not just delete. Reporting a phishing page gets it taken down for the next victim.
