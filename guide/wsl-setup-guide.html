🐧 SE Lab on WSL

Your own setup guide · install the full social engineering arsenal on your Windows laptop, the clean way

Every command in this guide was installed and test-run first · versions pinned to what actually works

Step 0 · Get the right WSL

Open PowerShell as Administrator on Windows and run:

wsl --install -d Ubuntu-24.04 wsl --update

Reboot if Windows asks, open Ubuntu 24.04 from the Start menu, and set your Linux username and password. Check you landed on the right version:

lsb_release -d # want: Ubuntu 24.04 python3 --version # want: 3.12.x (theHarvester 4.11.1 refuses anything under 3.12)
Why Ubuntu 24.04 specifically: it ships Python 3.12 out of the box. On Ubuntu 22.04 (Python 3.10) the newest theHarvester will not install at all, and that one version detail is the trap that eats an evening. Kali WSL also works with this guide, since it is Debian-based too.

Step 1 · The folder layout (do not skip this)

One root folder, tools grouped by job, each Python tool in its own virtual environment so their dependencies can never fight each other. This exact layout is what the installer builds:

~/se-lab/ ├── bin/ # one-command launchers: sherlock, maigret, gophish, ... ├── osint/ # recon tools + one venv per tool │ ├── venv-sherlock/ venv-maigret/ │ ├── venv-harvester/ theharvester-src/ │ └── venv-holehe/ ├── phishing/ # gophish/ evilginx/ set/ zphisher/ ├── venv-set/ # SET's dependencies live here ├── scripts/ # the installer + your update scripts ├── guide/ # these HTML guides └── work/ # demo outputs, Maigret reports, captured test data
⚠️ The WSL golden rule: keep the lab inside the Linux home (~/se-lab), never under /mnt/c. Files on the Windows drive are slow through WSL and get wrong permissions, which breaks venvs and PHP in confusing ways. Your Windows browser still reaches everything: WSL forwards localhost automatically, so Gophish at https://localhost:3333 just opens.

Step 2 · The fast path (about 10 minutes)

Save wsl-setup.sh (attached with this guide) into your Windows Downloads, then in your WSL terminal:

cp /mnt/c/Users/$USER/Downloads/wsl-setup.sh ~/ # adjust the Windows username path if needed bash ~/wsl-setup.sh

The script installs system packages, builds every venv, downloads the Gophish and Evilginx binaries, clones theHarvester at the working version plus Zphisher, installs SET from the official archive, creates the launchers, adds ~/se-lab/bin to your PATH, and finishes by actually running each tool to prove it works. When it prints SE LAB READY, open a fresh terminal and type sherlock --version.

Prefer Kali WSL? The same script runs there unchanged. On Kali you also have the shortcut for SET alone: sudo apt install set, because Kali packages it natively. Ubuntu does not, which is why the script fetches the official archive instead.

Step 3 · The manual path (every tool, command by command)

Same result as the script, typed by hand. Best way to learn what the script does. Start with the base:

sudo apt update && sudo apt install -y git curl wget unzip python3 python3-venv python3-pip php-cli build-essential mkdir -p ~/se-lab/{osint,phishing,bin,scripts,guide,work} cd ~/se-lab

🔍 Sherlock

python3 -m venv osint/venv-sherlock osint/venv-sherlock/bin/pip install sherlock-project osint/venv-sherlock/bin/sherlock --version

🕵️ Maigret

python3 -m venv osint/venv-maigret osint/venv-maigret/bin/pip install maigret osint/venv-maigret/bin/maigret --version

🌾 theHarvester (source build, pinned version)

git clone --depth 1 --branch 4.11.1 https://github.com/laramies/theHarvester osint/theharvester-src python3 -m venv osint/venv-harvester osint/venv-harvester/bin/pip install ./osint/theharvester-src osint/venv-harvester/bin/theHarvester -h
The trap: pip install theHarvester gives you a dead 0.0.1 stub package that does nothing. The real tool is installed from the cloned source, at tag 4.11.1, the newest release that runs on Python 3.12 (the very latest code already demands 3.14).

📧 Holehe

python3 -m venv osint/venv-holehe osint/venv-holehe/bin/pip install holehe osint/venv-holehe/bin/holehe --help

If Holehe ever crashes instantly with a URL parsing error, your shell has a broken NO_PROXY list. The launcher in Step 4 already shields you from it.

🎣 Gophish (binary, nothing to compile)

curl -sL -o /tmp/gophish.zip https://github.com/gophish/gophish/releases/download/v0.12.1/gophish-v0.12.1-linux-64bit.zip mkdir -p phishing/gophish && unzip -o /tmp/gophish.zip -d phishing/gophish chmod +x phishing/gophish/gophish

👑 Evilginx (binary, nothing to compile)

curl -sL -o /tmp/evilginx.zip https://github.com/kgretzky/evilginx2/releases/download/v3.3.0/evilginx-v3.3.0-linux-64bit.zip mkdir -p phishing/evilginx && unzip -o /tmp/evilginx.zip -d phishing/evilginx chmod +x phishing/evilginx/evilginx

No Go installation needed for either tool. The authors ship ready Linux binaries, which is faster and removes a whole class of build errors.

🧰 SET (official archive + own venv)

curl -sL -o /tmp/set.tar.gz https://github.com/trustedsec/social-engineer-toolkit/archive/refs/heads/master.tar.gz tar xzf /tmp/set.tar.gz -C /tmp && mv /tmp/social-engineer-toolkit-master phishing/set python3 -m venv venv-set venv-set/bin/pip install -r phishing/set/requirements.txt cd phishing/set && ~/se-lab/venv-set/bin/python setoolkit

First launch asks you to accept the terms and generates its config. Metasploit-dependent payload menus stay disabled unless Metasploit is installed, which is fine for phishing demos.

📱 Zphisher

git clone --depth 1 https://github.com/htr-tech/zphisher phishing/zphisher cd phishing/zphisher && bash zphisher.sh

Zphisher serves its pages with PHP, which is why php-cli is in the base packages. Without it the menu opens but no page is ever served.

Step 4 · Launchers, so it feels like Kali

One tiny script per tool in ~/se-lab/bin, then that folder on your PATH. After this, you just type the tool name from anywhere.

printf '#!/usr/bin/env bash\nexec ~/se-lab/osint/venv-sherlock/bin/sherlock "$@"\n' > ~/se-lab/bin/sherlock printf '#!/usr/bin/env bash\nexec env -u NO_PROXY -u no_proxy ~/se-lab/osint/venv-holehe/bin/holehe "$@"\n' > ~/se-lab/bin/holehe printf '#!/usr/bin/env bash\ncd ~/se-lab/phishing/gophish && exec ./gophish "$@"\n' > ~/se-lab/bin/gophish chmod +x ~/se-lab/bin/* echo 'export PATH="$HOME/se-lab/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc

The installer creates all eight launchers for you (sherlock, maigret, theharvester, holehe, gophish, evilginx, setoolkit, zphisher). The three above show the three patterns: a venv tool, a venv tool with an environment fix, and a binary that must start inside its own folder.

Step 5 · Verify like you mean it

sherlock --version maigret --version theharvester -h | head -3 holehe --help | head -3 php --version | head -1 ls ~/se-lab/phishing # gophish evilginx set zphisher

Then one live-fire test on a public test account, so you know the network side works too:

sherlock --site GitHub octocat # should find github.com/octocat

🔄 Keeping it fresh + daily use

  • Update the pip tools: ~/se-lab/osint/venv-sherlock/bin/pip install -U sherlock-project (same pattern for maigret and holehe).
  • Update theHarvester: cd ~/se-lab/osint/theharvester-src && git pull then reinstall into its venv.
  • Gophish panel: start gophish, open https://localhost:3333 in your Windows browser, user admin, password printed in the WSL terminal on first start.
  • Class demo on localhost: in Zphisher pick the localhost tunnel option, and the fake page opens in your Windows browser at the shown address, fully offline-safe.
  • Shut WSL down cleanly when done: wsl --shutdown from PowerShell.
  • Backup the whole lab: it is one folder. tar czf se-lab-backup.tar.gz ~/se-lab and copy the archive to your D: drive.
Lab rules, always: demo accounts you own, isolated practice, never real people. The same toolkit aimed at strangers is a crime, and in class the defence half of every demo matters as much as the attack half.
